# Отчёт по лабораторной работе: предсказание стоимости автомобиля

## Что было сделано

### Предобработка данных
- Удалены дубликаты из тренировочной и тестовой выборок
- Обработаны числовые признаки: из колонок `mileage`, `engine`, `max_power` удалены единицы измерения, значения приведены к типу `float`
- Реализован парсер колонки `torque`: извлечены момент силы с переводом из kgm, при необходимости, и обороты `max_torque_rpm`; таким образом из одного текстового признака получено два числовых
- Пропуски заполнены медианными значениями, посчитанными на тренировочной выборке
- Из полного названия автомобиля (`name`) извлечена марка - первое слово строки

### Построение моделей

Все модели обучались на тренировочной выборке, качество оценивалось на тестовой

| Модель | Признаки | Бизнес-метрика |
|---|---|---|
| LinearRegression | только вещественные | 0.04 |
| LinearRegression | вещественные + StandardScaler | 0.04 |
| Lasso | вещественные + StandardScaler | 0.04 |
| Lasso | вещественные + StandardScaler + GridSearch | 0.11 |
| ElasticNet | вещественные + StandardScaler + GridSearch | 0.11 |
| L0Regressor | вещественные + StandardScaler + GridSearch | −1.00 |
| **Ridge** | **вещественные + OHE + StandardScaler + GridSearch** | **0.35** |

Лучшая модель — Ridge с параметром `alpha=1` (подобран через GridSearchCV, `cv=10`):
- **R^2 = 0.78**
- **MSE = 125 044 782 076.75**

### Деплой сервиса

На базе FastAPI реализован сервис с двумя эндпоинтами:

- `POST /predict_item` - принимает JSON с признаками одного автомобиля, возвращает предсказанную цену
- `POST /predict_items` - принимает CSV-файл с признаками нескольких автомобилей, возвращает CSV с дополнительным столбцом `predicted_price`

Сервис развёрнут в Google Colab с туннелем через ngrok. Предобработка внутри сервиса воспроизводит весь пайплайн из ноутбука: очистку строк, парсинг torque, заполнение пропусков медианами трейна, масштабирование через сохранённый `StandardScaler`, кодирование категорий через сохранённый `OneHotEncoder`

## С какими результатами

Лучшая модель (Ridge) объясняет **78% дисперсии** целевой переменной на тестовой выборке. Бизнес-метрика выросла с 0.04 до **0.35** — почти в 9 раз по сравнению с базовым LinearRegression.

Примеры предсказаний сервиса:

| Автомобиль | Реальная цена | Предсказание | Ошибка |
|---|---|---|---|
| Maruti Swift Dzire VDI, 2014 | 450 000 ₹ | 464 341 ₹ | ~3% |
| Tata Nexon, 2017 | 665 000 ₹ | 695 826 ₹ | ~4.6% |

## Что дало наибольший буст в качестве

Самый значительный прирост - переход от моделей только на вещественных признаках к **Ridge с OHE категориальных признаков**: бизнес-метрика выросла с 0.11 до 0.35. Категориальные признаки (`fuel`, `seller_type`, `transmission`, `owner`, марка автомобиля) несут большую часть информации о цене, и их включение кардинально модель

Дополнительный вклад внесли:
- Парсинг `torque` -> два информативных числовых признака вместо одного текстового
- Подбор гиперпараметров через GridSearchCV (у Lasso буст с 0.04 до 0.11)

## Что не вышло и почему

**get_dummies вместо OneHotEncoder** - `pandas.get_dummies` не поддерживает параметр `handle_unknown='ignore'`, из-за чего на тестовых данных с новыми категориями модель падала с ошибкой. Пришлось использовать `sklearn.OneHotEncoder`, который корректно обрабатывает незнакомые категории

**L0Regressor** - модель показала бизнес-метрику -1.00, что хуже любого базового решения. Вероятно, алгоритм не подходит для данной задачи при текущем наборе признаков и гиперпараметров, либо требует более тщательной настройки

**FastAPI вместо Streamlit** - по заданию сервис предполагалось реализовать на Streamlit, однако у многих возникали проблемы с запуском приложения при активном VPN. В качестве альтернативы был выбран FastAPI - он решает ту же задачу (два эндпоинта для предсказания), запускается в Google Colab через ngrok и не конфликтует с сетевыми настройками

**Отладка сервиса** - при первом запуске predict_item возвращал некорректный результат (отрицательная цена в миллиарды). Причина обнаружилась через добавление отладочного print в функцию preprocess: сервер использовал кэшированную версию main.py и не подхватывал изменения. Проблема решена через importlib.reload. Вторая причина некорректных предсказаний -забытый StandardScaler: модель обучалась на масштабированных данных, а сервис подавал сырые числа. После сохранения и подключения scaler.pkl предсказания стали адекватными
